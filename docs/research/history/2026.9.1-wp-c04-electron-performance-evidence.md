### 稳定复测与剩余根因

单次 cold/warm 结果受 Chromium 调度影响较大，后续使用按操作隔离 Long Task cursor、40 个 RAF 边界和 idle settle 的 harness 重新执行 3 次 cold + 3 次 warm。manifest：

```text

```

- video/image 的 masonry/album 四种布局在 6 次运行、共 24 个操作窗口中均未暴露 Long Task；旧记录中的 `126–128ms` video album 和 `79–94ms` image masonry 未复现。
- video detail open 6 次均无 Long Task；return 为 cold `54/58/58ms`、warm `52/53/57ms`。
- image detail open 6 次均无 Long Task；return 为 cold `75/65/64ms`、warm `67/65/71ms`。
- 12 次 detail return 的 scroll error 均为 `0px`。

因此布局切换已达到当前操作级证据门槛；未达标面收敛为 detail return，以及操作窗口外另行观察到的首次 History route 和 image tab switch。不能再用旧单样本把布局切换列为主要瓶颈。

对 detail return 做了 controller 生命周期保留实验。实验后的 actual manifest 为：


结果仍为 video return cold/warm `53/63ms`、image return cold/warm `63/63ms`，四种布局仍无 Long Task。cold trace 中 video 的 `53.877ms` 任务由 `FireAnimationFrame 27.60ms`、Layout/UpdateLayoutTree/Layerize/Paint/PrePaint 约 `23ms` 构成；image 的 `63.034ms` 任务对应 `FireAnimationFrame 35.76ms` 和渲染阶段约 `24.6ms`。RAF 内可归属的 JavaScript callback 仅约 `0.004ms`。这证伪了“列表 controller 全量 remount 是剩余主因”：主因是 500-card subtree 从 detached `DocumentFragment` 重新接入文档后，Chromium 在首个 RAF 重建 rendering state。该 controller 实验已撤回，不保留额外 lifecycle 分支。

若继续要求所有路径严格 `<=50ms`，下一步不是继续调整 observer batch 或 RAF 延迟，而是单独评审 DOM 生命周期方案：detail 往返需要 connected rendering cache；首次进入和 tab switch 需要分帧 materialization 或虚拟化。这会触碰当前“500 张语义卡片始终存在于 DOM/可访问树、完整 Find in page 与 Tab 顺序”的 preserve contract。

### 用户接受决策（2026-09-01）

用户确认当前速度可以接受，并决定不为剩余 `2–25ms` 的 detail return 超预算承担 connected DOM cache、分帧 materialization 或虚拟化的实现与回归成本。History 性能项按“已显著改善、接受实测剩余偏差”收口：保留完整语义 DOM、现有可访问性、筛选/排序、媒体调度和精确滚动恢复，不再继续追加性能特判。该接受决策不等于把 `<=50ms` 严格预算标记为技术通过，也不解除 C04 的其他 Closure Gate。

交接给后续 Agent：不要继续优化 History Long Task，不要恢复已证伪的 controller 生命周期实验，也不要引入虚拟化。收尾工作只需保留当前实现、运行既定验证、准确报告 accepted residual；只有用户重新明确要求，或真实数据稳定达到上千条并出现不可接受体验时，才重新打开性能架构评审。
