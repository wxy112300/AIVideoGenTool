# 历史规模与快速切换性能复核

日期：2026-10-24。范围：性能检查与可直接定位的局部修正，patch。用户库、模型执行及持久化格式不变。

## 实测方式

- 隔离生产 Electron：分别每类 500 条和 1500 条视频/图片记录，复用隔离物理媒体文件；不同记录 ID/版本/比例，包含缺文件、收藏和不同日期。不是 3000 个独立媒体文件的 I/O 压测，也不是 GPU 生成测试。
- CDP 原生鼠标/键盘操作，1440×1000、focus emulation；记录 PerformanceObserver longtask（50ms 门槛）、双 rAF 后的操作耗时、CPU profile、DOM/播放器数量。机器同时有用户应用，封面缓存随访问变暖；各轮不是严格冷缓存 A/B，不能将全部差值归因某项修复。
- 后台窗口的 rAF 采样出现 33/50ms 等间隔，不把它解释成前台显示器帧率或宣称稳定 60fps。

## 定位与修复

1. 全量列表为每张卡创建 HTMLVideoElement，即使只显示封面。改为卡片保留媒体 URL、封面照常按视野调度，交互才创建静音循环预览；支持已有 video 节点，离开仍释放解码资源。500/1500 条初始列表视频元素为 0，实际悬停播放后仅出现所需播放器。
2. 共享 UI MutationObserver 将媒体、提示等新增节点当作控件更新，触发整页扫描。改为只筛选新增控件/帮助来源，刷新受影响父节点并合并嵌套范围；移除控件仍释放 select/segment。动态新按钮和下拉照常增强，媒体插入不会扫描全页。
3. 时间轴逐条搜索卡片，并交错读位置/写标记。改按 ID 建 Map、先批量读位置再写标记，减少大日期跨度下的查找与强制布局。
4. 1500 条快速导航实际失败：最后停在较早的页面，捕获的点击目标落到快照下的根节点。仅添加 `pointer-events:none` 仍不足，因为命名顶栏自身被快照替代。最终取消根/顶栏快照，只命名主内容；快照层不拦截输入，保留 90ms/160ms 与 4px 动画，顶栏始终是真实交互节点。DESIGN 动效说明同步此实现。

## 数据与边界

| 场景 | 初轮 500 条 | 局部修正后 500 条 | 最终 1500 条 |
| --- | ---: | ---: | ---: |
| 首次视频列表（含 CPU 采样开销） | 434ms | 407ms | 698ms |
| 图片列表 | 732ms | 294ms | 865ms |
| 再切视频 | 359ms | 191ms | 597ms |
| 从创建返回历史 | 374ms | 309ms | 659ms |
| 连续滚动长任务 | 无 | 无 | 1 次 52ms |

500 条数据是修复步骤中的样本，最终 CSS 转场目标改变后再测了 1500 条，不拿不同缓存轮次计算加速百分比。

**仍有结构性瓶颈**：1500 条会建立约 6.5–6.9 万个元素，最终列表重建仍有 200–405ms 长任务。局部优化不能让上千条全量 DOM 重建完全流畅；下一步需要窗口化/虚拟列表，同时保护瀑布流估算、时间轴跳转、筛选与批量选择、键盘可达性、详情返回锚点。此次没有通过截断记录数或删除功能掩盖瓶颈，也不将“大规模流畅度”标为完成。

## 功能与验证

- 完整 `npm.cmd run verify`：2525 单元、91 集成、桌面/Web 构建及 440 对比检查通过。包含原 500 条 synthetic benchmark 的媒体并发/按视野调度断言；不是用静态通过推断流畅。
- 新增回归覆盖无交互不创建播放器、重复交互复用节点、无源不创建；媒体新增不重扫全页，动态控件仍增强。相邻媒体控制、时间轴、可访问性测试通过。
- 最后转场 CSS 修正后，重新 typechecked build、440 对比检查和真实 1500 条压力验证通过：20 次 45ms 间隔切页最终 History 正确，唯一列表；收藏筛选 1500→500→1500；六次 Page Up/Down 有两种实际版本源且只有一个详情播放器；鼠标悬停播放时间推进、离开后暂停、返回父页可达。队列/草稿/视频历史/图片历史的 renderer SHA256 摘要一致。
- 最终截图、CPU profile、计时与长任务原始数据位于本地 `temp/ui-perf/`，不纳入提交。不把一轮 DOM 计数作为无内存泄漏的证明。
