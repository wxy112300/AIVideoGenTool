# 历史详情双向短转场

日期：2026-10-25。patch；用户要求为历史列表进入/退出详情补短动画，并查阅常见 iOS 设计原则。

## 设计依据

查阅 [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion) 与 [Enhancing your app with fluid transitions](https://developer.apple.com/documentation/uikit/enhancing-your-app-with-fluid-transitions)：用运动解释导航关系、保持固定参照、允许中断并适配减少动态。Apple 的 fluid zoom 是另一种基于来源缩略图的连续导航；本次选择符合现有媒体+参数桌面布局的短距离推入/回退，不包含共享缩略图缩放或手势拖拽返回。

| 阶段 | 内容动画 |
| --- | --- |
| 进入详情 | 列表 90ms 向左 10px 淡出；详情 220ms 从右侧 24px 淡入 |
| 返回列表 | 详情 90ms 向右 18px 淡出；先恢复列表锚点，再用 180ms 从左侧 14px 淡入 |
| 减少动态 | 省去退场与位移，只淡入 120ms |

这些是本产品的动画设计值，布局与素材就绪另计；没有据后台截图/rAF 推断显示 FPS 或真实端到端耗时。顶栏、历史标题、媒体导航、筛选与详情返回/翻页行均不参加移动。详情内部切换作品不重放本组动画。

## 实现与发现

- 保持 M9f 的真实 DOM 动画，不引入原生整页快照覆盖层。内容横向裁剪避免短位移增加页面宽度。
- 取消过时退场，只有最新请求可提交；保留列表的退场动画在提交后清除，避免恢复出一个透明的原列表。
- 实际中断测试发现旧页监听在动画开始前已被 lifecycle 清理，导航看得见但无法响应。现由 render coordinator 在真正提交 DOM 时调用清理，异步加载与退场期间旧页仍可交互；事件刷新也沿用同一清理入口。
- 忽略已经请求的同一页导航，防止连续返回时用详情滚动值覆盖已保存的列表锚点。

- 真实 Electron：隔离 36 视频/10 图片作品夹具，1280×900，focus emulation。实际点击卡片、返回按钮及播放按钮；视频和图片各保存进入/返回 8 张中间截图。四条进出路径的逐帧记录确认顶栏 top=0、opacity=1、命中真实导航，未出现原生转场覆盖层或导航祖先动画。
