# 详情进入时列表首页闪回

日期：2026-10-25。patch。用户实测指出 M9g 在退场之后闪出完整列表首页，再切详情；原先抽样截图和关键帧验证未覆盖这个顺序错误。

## 连续录帧复现

真实 Electron，隔离 36 视频/10 图片夹具，1280×900、focus emulation。使用 CDP `Page.startScreencast`、`everyNthFrame:1`，收到画面即 ACK 并保存，同时独立记录 rAF 下的实际 DOM、滚动与可见性；不再通过顺序调用截图来代替连续合成器记录。

未修复构建：点击处的列表 scrollY=2636；随后 7 条采样记录出现仍可见的列表 scrollY=0，合成器 `before/frame-003.jpg` 直接显示首批作品，而非点击时末尾作品。共收集 39 张合成器画面。该验证只代表浏览器上报画面，不推断物理屏幕帧率。

## 根因与修正

1. `resetHistoryDetailScroll` 根据请求路由立即归零，并再跨两帧重复；引入 90ms 退场后，此时旧列表尚未离场。因此先将它滚回首页，才开始挂载详情。现要求实际详情 DOM 已存在才能执行该兼容重置；跨模块的独立 rAF 归零也移除，由 presentation 在提交后统一处理。
2. AV 检查等相同目的页刷新会取消、重建退场，恢复旧列表的透明度。现同一目的页复用退场动画，只允许最新请求提交和清理；不同目的页仍可取消。取消旧请求不会清理另一个请求正在共用的动画。

新增测试分别验证：请求详情但仍显示列表时不滚动；同目标刷新不重启动画、不取消共享退场，旧提交无效。
