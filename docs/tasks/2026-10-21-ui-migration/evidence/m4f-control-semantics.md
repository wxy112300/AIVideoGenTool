# M4f：清晰度与续写语义复测修正

2026-10-22，patch 影响。本批以用户复测纠正为准，取代 M4e 的“1080 离散端点”和“续写生成方式替换为路线名”决定；M4 图片页和剩余长视频表现未完成。

## 修正

- 公共分段选择器观察同一 DOM 内的选择变化，重新定位底块并播放滑动动画；减少动态效果仍遵从设置。
- 标准 H3 自定义短边按 16 连续取值，有效上限由当前模型及功能条件决定。上限为 1080 时允许 784、832、848、864、992、1072 等中间值；精确 1080 仍走现有专用路线。草稿数字字段与队列快照结构不变。
- 分辨率输入同步尺寸和提交条摘要，拖动期间不反复写入未变的 min/max/step/value/disabled。使用指针捕获跟踪拖动，避免此次真实 Electron 测试复现的原生 range 收到移动却不产生 input 的情况。
- 原生锁定推荐采样预算，只有明确选择原生解锁才放宽；输入大值不再自动解锁。Continuum 多段入口仍为已授权的本地 UI 演示，未接真实多段执行。Motion Context 只隐藏该入口。
- Extend 显示新增时长上限，复用现有时间规划扣除分支重叠并满足帧数对齐。后台 duration 本来就是新增时长，不再重复扣除；既有队列和托管段长冻结不变。
- 双手柄裁剪退出公共单滑块材质，轨道/手柄限制在 44px 容器内；去除圆头底及溢出。删去常驻的重复解释、文件路径及所有权文案；保留实际检查/失败反馈与操作入口。

| 续写路线 | 原生新增上限 | 解锁新增上限 |
| --- | --- | --- |
| FL2VA 边界续写 | 15.0 秒 | 29.9 秒 |
| R2V Motion Context | 13.6 秒 | 29.0 秒 |
| Continuum | 14.1 秒 | 29.0 秒 |

差异来自各路线继承前缀与时间对齐；总采样窗口仍对应原生 15.1 秒、解锁 30 秒。托管序列的既定 chunkSeconds 保持冻结。

真实生产 Electron 使用隔离 userData 与离线 runtime：

- 实际点击 480→720，底块位移 92→364，采到 178.868、304.379 等中间帧，最终准确停在选中位置；提示词及选择器保持挂载。提交条更新为 `1280 × 736 · 5.0s · 24 FPS`。
- 实际输入上述六个中间分辨率，草稿保留原值，尺寸读数与底部摘要一致。832p 经实际加入队列按钮生成任务 `c0c1d928-53f8-4711-bb18-d06d96857f4e`，没有错误附加 1080 交付字段；缺少提示词后补齐并恢复可提交。
- 创建原生输入 30 被限制到 15.1，明确选择解锁后上限 30。实际模型/生成方式下拉逐项验证表中三条续写路线的上限；Motion Context 只有原生/解锁。
- Extend 分辨率六次往返真实鼠标拖动，102 次 input、25 个不同值（336–720）；滑块和视频节点保持挂载。裁剪由 8 秒拖到约 5.6 秒，并同步预览定位。
- 1440/1120/900/820 四宽度下无横向溢出，裁剪区高 44px，所有子元素均在父容器内，输入背景圆角为 0。正常 Motion Context 状态行实际隐藏，可选文件行简化为“未选择（可选）”。
- 全部编辑后深比较已入队任务不变，队列未启动。

本轮先测出 Extend 原生滑块拖动无 input，修正指针捕获后重新构建、完整 verify，并以新隔离窗口重跑上述检查。不能将上一轮仅有 DOM 身份稳定的证据等同于动画或拖动正确。

## 同日续修：自定义填充与警告颜色

用户截图显示原生 thumb 已在 768 端点，但蓝色填充停在旧值。原因是程序设置 range.value/min/max 不触发 input；清晰度控制器现于 paint 完成后调用公共填充计算，避免伪造编辑事件。时长警告原有黄色规则在 legacy 层，被 patterns 层通用 field-info 灰色覆盖；在当前参数样式层明确设置警告色。

聚焦控件与公共 UI 测试 10 项通过；完整 verify 再次通过 2433 单元、91 集成、740 对比度。真实生产 Electron 点击 768/480/720 后切自定义，在 256–768 范围下填充分别为 100%、43.75%、90.625%；扫描后上限变为 1080，画面填充继续与当前值相符。解锁后输入 20 秒，警告容器及 SVG 计算色均为 `rgb(255, 202, 22)`，与 warning token 一致；切回原生后警告隐藏。实际加入队列得到任务 `68c0fa9b-17df-42de-b8e1-ab8877dc7220`，保留 720p 参数。报告和截图为 `temp/ui-m4f/fill-report.json`、`fill.png`；自有隔离窗口清理，未运行 GPU。

## 同日再次复测：填充与圆点的像素对齐

用户再次提供 540p 截图，蓝色填充伸出圆点。上一轮计算比例检查不足以证明像素对齐。本轮隔离生产窗口未精确复现截图中约 48px 的伸出量，不能将其全部归因为下面两个已确认问题：

- 原生 range 的 256/16 网格会把已有 540 档控件值自动变为 544。滑块改为接受精确值，输入归一化继续由现有应用控制；显式方向键处理保持 16 步进，连续按键不会卡在同一值。队列尺寸几何对齐规则不变。
- 背景填充原按全宽百分比计算，圆点中心却在两端各缩进 9px 的行程中运动。公共填充现在按 `9px + (width - 18px) × ratio` 定位。

最终源码完整 verify 通过（2433 单元、91 集成、740 对比度）。1440/820 两宽度分别真实点击 360/480/540/768/1080 后切自定义，取得十张截图；用 PNG 像素检查蓝色终点接到白色圆点左缘、未出现在圆点右侧，圆点中心距数值预期位置小于 1.5px。540 控件值与数字框均为 540，另有方向键 540→560→576 的回归断言。像素报告为忽略目录 `temp/ui-m4f/alignment-pixel-report.json`，截图 `alignment-1440-540.png`。

同一生产窗口复核警告黄/原生隐藏及 720p 实际按钮入队，任务 `b26da4c7-dbcc-4be4-b48a-250b984d0609`；未运行 GPU。自有隔离窗口完成清理，未操作用户正在使用的窗口。
