# 文档目录资料库迁移与 NAS 自动同步计划

类型：实施计划；日期：2026-10-27。当前状态、执行归属及后续进度只由 [TASK](TASK.md) 维护。本文件描述目标与验收，不代表现行实现；现有产品边界见 [Architecture](../../ARCHITECTURE_CONTRACT.md)，NAS 前置见 [原任务](../2026-10-27-nas-browser/TASK.md) 和 [工具手册](../../../Tools/NasBrowser/README.md)。

## 1. 已确认的方向与范围

- 用户希望资料库默认放在“我的文档”，旧资料自动迁移，无需逐条重新导入；另一台电脑已有约 1200 个历史作品，完整性和可恢复性优先。
- 电脑继续创作并拥有资料的唯一写入权；群晖 DS418play、DSM 6.x、已有 Docker，Drive 只从电脑上传到 NAS。NAS 保留现有手机优先浏览，不提供收藏、评分或 Tag 编辑，不反向同步。
- PC/NAS 根路径可以不同；视频仍留在 Output，封面缓存继续留 AppData/history-covers/v3。迁移不重建作品 ID，不移动媒体、续写 payload 或 Run，不触发封面/GPU 重生成。
- 日常无需手动导出或额外运行 CLI；App 在后台自动维护同步资料。App 关闭后 NAS 读取最后完整到达的资料。
- 后续确认：App 设置不增加 NAS 发布目录；浏览投影自动置于当前 Library 的 StudioLibrary 子目录，Drive 软件自行配置上传来源和 NAS 目的地。
- 最新确认：历史数据目录默认 Documents；用户手动修改资料库、视频或图片输出路径时，必须先确认再真实移动并显示进度，不能仅复制或只改路径。视频/图片新位置限定当前 ComfyUI output 根内。首次从旧 state 建库仍保留原始配置，后续主动搬迁成功后移除已迁移源文件。
- 计划建立时仅授权规划；后续用户已授权实施，并要求先在本机准备实现与配置。当前范围/验证/现场阶段由 TASK 维护；本计划本身不授予实库删除、部署、版本升级或发布权限。

不包含创作功能上 NAS、实时转码、云端多写入者、自动合并两台电脑的主资料库、NAS 图片浏览、密码/配对或旧版本 App 自动降级兼容。图片历史在桌面资料库迁移中必须保持独立集合与完整性，不因 NAS 仅浏览视频而丢弃。

## 2. 计划建立时的问题与风险依据

1. `studio-state.json` 同时保存设置、草稿、队列、视频和图片历史；整个文档重写会随历史增加变重。
2. `JsonStore.load` 的宽 catch 会把非 ENOENT 错误尝试归档为 .corrupt，再创建默认状态；I/O、迁移、权限错误不能都视为“新用户空库”。
3. `replaceStateFile` 通常 rename，Windows 反复拒绝时可覆盖复制；它不能替代写前有效备份、完整性校验和恢复流程。
4. 已有 NAS 工具把多版本 Prompt 放在单个 catalog 中，并定时读取整份资料。64 MiB 上限是保护，不是扩展性设计；坏索引的最后有效快照目前仅在进程内，重启后仍需可用磁盘版本。
5. Drive 同步顺序不受 App 事务控制，单向同步也可能传播错误/删除；不能把“上传完成”当作备份或跨文件事务提交。

## 3. 存储与同步目标

```text
AppData
  设置 / 草稿 / 队列 / 资料库定位与迁移记录 / 可重建桌面索引 / v3 封面缓存
       ↓ 通过现有 StateRepository 组合读取；维持 AppApi 的 history 快照兼容
系统“文档”/Local Video Studio/Library
  library ID 与格式版本 / 分作品完整记录 / 文本对象 / 提交记录 / 有效备份
       ↓ App 后台投影（只含浏览字段，不直接同步整个主库）
Drive 正在上传的资料目录/StudioLibrary/<libraryId>（可位于文档资料库下，与 Output 独立）
  分作品浏览记录 / 按需 Prompt / 内容寻址封面 / 轻量提交清单 / 删除标记
       ↓ Drive 单向上传（不依赖跨文件到达顺序）
NAS 只读挂载目录
       ↓ 校验已提交记录，增量更新
NAS 独立 /data 中的 SQLite 查询索引与最后有效版本
       ↓ 筛选、排序、分页、完整视频播放
手机 / iPad / PC 浏览器
```

- 默认路径通过 `app.getPath("documents")` 获取，支持系统文档已重定向；不拼接用户名或固定 C 盘。保留可选的资料库位置设置，按现有两列设置布局提供路径、选择/打开和必要错误状态，不新增说明卡片或改版。
- AppData 的定位记录与 Documents 的 library ID/commit 共同确定当前库；文档路径临时离线、权限错误或定位记录损坏，不得导致自动初始化覆盖旧库。
- 每个作品一份带 schema/revision/校验信息的完整记录；视频与图片集合分开。Prompt/长文本按内容引用保存，避免同文在多版本中重复。具体文件名映射须安全编码，不能把未经校验的 ID 当路径。
- 轻量清单只记录库身份、提交代次和记录引用，不内嵌全部详情、Prompt 或执行图；清单损坏能从有效记录、提交记录与删除标记重建，不复活已经删除的作品。
- 完整生成参数、版本关系、图输出描述与辅助 owner 引用属于桌面主库；NAS 只接受浏览投影，主库字段不得为了瘦身被直接丢掉。
- SQLite 仅为可重建索引，不是 Drive 同步对象；桌面索引放本机 AppData，NAS 索引放 NAS 自己的 /data。正式采用前验证 Electron/Node 驱动、打包与 DSM 6 容器可运行性。
- 两台 PC 以不同 library ID 隔离发布路径，不互相覆盖。首版先单库配置；跨库聚合与冲突合并不隐含在本次迁移中。

## 4. 写入、备份与恢复要求

- 同一库单写入者；串行事务包含候选记录写入、校验、必要持久化、提交标记和定位切换。文件 rename 本身不能当作完整掉电恢复保证。
- 写失败时保留最后已提交状态和错误原因，不向 UI 报成功、不向 NAS 发布空库或半份库；后续保存失败也不得被启动的默认状态覆盖逻辑吞掉。
- 保留多代经过 schema/内容校验的有效快照和迁移前完整旧 state。建议区分近期提交与每日快照，具体数量/空间上限在 P0 固定；本次不自动删除任何现有备份。
- 恢复时按库身份与完整提交代次寻找最近有效备份，恢复到候选位置并验证后切换；保留损坏原件和恢复来源，不能只因 JSON 能解析就认定资料完整。
- 没有有效备份时进入可见恢复状态，允许重试、选择已有库或显式新建；新建必须说明后果，不能把权限错误当作首次启动。
- 删除记录使用明确的提交/删除标记并进入备份；索引重建不能扫描旧备份后把已删除记录重新纳入主库。
- 自动回退仅适用于尚未切换的迁移阶段。新库已有新增/编辑后，不能静默回退到迁移前旧库丢弃新修改；需明确的恢复流程。

## 5. 首次迁移事务

1. **识别来源与状态**：在 Queue/runtime 与历史写入启动前判断全新安装、待迁移、迁移中、已切换或待恢复。读取旧 state 必须先经过非破坏校验，不能先调用会在失败时写默认值的旧 load 路径。
2. **取得一致性来源**：记录源内容校验与格式版本，制作完整备份并重新读回校验；迁移期间不接收重叠历史写入。外部修改源文件时重新核对，不能拿过期快照切换。
3. **准备目标**：解析系统 Documents，检查可写、目标是否已有不同库及可用空间；只写本次候选目录和迁移记录，不覆盖已有库。空间/权限失败时旧库保持可用。
4. **复制完整资料**：视频、图片与所有版本逐项迁移，保留全部持久化字段及身份；原文件缺失、AV 已删除、跨盘路径、派生关系等也原样保留，不通过“现有文件扫描”重建或筛掉历史。
5. **验证**：对比作品/版本 ID 集合、计数、语义内容校验、父子/Run/AV/Motion 引用和图片集合；以独立读取实例重开新库，而非只校验当前内存对象。未知持久化扩展字段不得无声丢失。
6. **提交并切换**：先确认目标完整提交，再更新 AppData 定位与迁移完成标记。进程在每个写入边界退出都能判断权威来源，重复启动不能重复导入或产生双主库。
7. **完成后保留旧备份**：新库是唯一继续写入的位置，设置/草稿/队列继续原位置。旧数据保留为明确的备份，禁止两份活动历史同时写入；旧版 App 不保证可读新格式，回退需按恢复说明处理。

迁移中断后按事务记录恢复/重试；只有最后校验并切换成功，才允许 App 后台向 NAS 发布新资料。不得为迁移/修复自动搬移或删除用户媒体。

## 6. 实施顺序与完成条件

| 阶段 | 工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 损坏保护 | 收窄 load 错误分类；有效备份、恢复入口、写失败保护；固定备份策略与事务格式 | 错误/损坏/丢文件/权限故障不会重建覆盖已有库；可从有效备份恢复 |
| P1 分作品存储 | 在 StateRepository 后实现完整记录与文本引用、单写者/提交/删除标记、可重建索引；保留 preload 与历史查询契约 | 完整 round-trip、旧记录与未知字段保留；仅修改目标作品；10000 条夹具读写/查询有记录 |
| P2 Documents 迁移 | 独立 migrator、启动定位、阶段恢复、目标库冲突、位置设置与路径错误恢复 | 1200 条隔离旧库首次迁移、重启、故障注入及 UI 旅程通过；实库未经明确验收不自动试跑 |
| P3 App 自动发布 | 订阅已提交变更并合并后台任务；增量记录/Prompt/封面发布，完整代次与删除标记 | 日常无需 CLI；App 退出保留已发布文件；失败/恢复/无变化不重复写；不存在损坏→空库同步链 |
| P4 NAS 增量浏览 | 导入新的分作品投影到本地 SQLite；事务索引/按需 Prompt/重建，兼容已完成前置的单 catalog 读取或明确升级路径 | 缺文件/乱序/损坏记录/重启不破坏最后有效库；查询与播放器沿用原 UI；/data 与媒体挂载权限正确 |
| P5 群晖部署 | 核对实际 DSM、内核和 Docker；验证维护中的运行镜像/SQLite 驱动，配置路径、只读挂载、服务持久化 | DS418play 冷启动、容器重启、PC 关机、手机/iPad 实际浏览通过；记录确切版本与未验边界 |

P0–P2 优先于自动发布；P3–P4 依赖相同发布协议，不能各自维护一套字段/版本来源。现有 NAS 工具仅作为可复用的界面/协议/部署基础，其单 catalog 不得继续被描述为最终存储方案。

## 7. 验收矩阵与数据边界

| 场景 | 必须证明 |
| --- | --- |
| 旧库 0 / 137 / 1200 条，1200 条含多版本/图片/长 Prompt/旧字段 | 所有 ID 与完整资料一致；第二次启动无重复迁移、无字段静默丢失 |
| 已有库损坏、只读、目录离线、磁盘满、备份损坏 | 正确区分错误；旧库与可用备份仍在；没有默认空库覆盖与 NAS 空发布 |
| 写临时文件/备份/提交/定位各边界中断 | 重启可继续或恢复最近完整代次，无双写、半库或重复记录 |
| 目标非空、不同 library ID、目标部分损坏 | 可见冲突与恢复，不覆盖别的库；旧活动库保留 |
| 路径含中文/空格、Documents 重定向、跨盘/缺媒体/已删除 AV | 媒体不移动；记录不丢弃；桌面路径引用与删除保护仍正确 |
| 历史筛选、详情、父页返回、播放、收藏/评分/标签、继续创作/入队 | 兼容现有 AppApi；修改不重建媒体；旧 queued 快照和来源身份保持；可见入口实际点击验证 |
| Drive 单文件截断、乱序、重复上传、删除标记先到/后到 | 校验和完整提交保护；只更新相关作品；待到齐自动恢复；不复活已删除项 |
| NAS SQLite 丢失/损坏、进程/容器重启 | 从有效同步资料重建；不用 PC 在线；不改同步源文件 |
| 10000 条合成记录及长 Prompt 压力 | 记录冷启动、内存、后台变更处理、分页延迟；未变化时不全库解析/重写，修改一条不复制全库 |
| 两个 library ID 指向同一个 NAS | 发布位置隔离；不以相同文件名/重叠 ID 覆盖另一个来源；不默认自动合并 |

先跑聚焦 Vitest、typecheck，再按 [CHANGE_VERIFICATION](../../CHANGE_VERIFICATION.md) 执行 verify 和受影响的真实 App/浏览器 UI。迁移/删除/故障注入全部使用物理隔离素材；不为了验收读取另一台 PC 或直接损坏实库。实库试迁移应先明确目标、制作可恢复备份并核对影响，再按已有授权执行。

本计划不要求重放 GPU 生成；如影响继续创作/队列快照，先用实际 UI 与隔离任务 ID 验证入口，真实生成是否必要按改动再决定。所有本次拥有的进程、监听与夹具在证据中列明并回收。

## 8. 实施前需固定的技术项

- 桌面存储/文本对象/提交清单的 schema、完整性校验、删除语义、备份保留量和空间不足策略。
- AppData 旧 state 与新资料库之间的兼容组合方式，以及启动失败/定位损坏时的恢复 UI；不新增第二套活动历史。
- NAS 发布协议及单 catalog 前置格式的兼容路径；SQLite 驱动和 Electron/Node/DSM 支持范围必须由实测确定，不直接假设兼容。
- 主资料库路径、浏览发布目录与媒体目录是独立概念；默认文档资料库可以被 Drive 上传，浏览投影可放其中的独立子目录。服务以 libraryRoot 与 mediaRoot 分别映射 NAS 上的资料/媒体；不要求发布目录位于 Output，原始主库不能未经投影直接当作浏览 catalog。两条上传任务保留各自相对层级。
- 用户另一台电脑的规模/版本特点、PC/NAS 实际路径、精确 DSM/Docker/内核与 NAS 地址留待真实配置时核对；不阻塞本地设计与隔离夹具。

这些是后续阶段的有限设计工作，不要求本次建计划时再次审批；若实现发现需要改变上述用户方向、合并现有库或删除旧数据，再明确说明影响。
