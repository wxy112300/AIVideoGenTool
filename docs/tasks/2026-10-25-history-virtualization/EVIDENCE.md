# 虚拟列表验收

2026-10-25，工作区 0.66.6 的未发布 patch；未改 IPC、持久化或模型执行规则。

## 实现边界

- 超过 80 条的列表登记完整轻量元数据与按需卡片渲染函数，不生成全库卡片 HTML。小列表保留原路径。
- `virtual-layout.ts` 根据现有列数、10px/8px 间隔、媒体比例、47px 文字区及边框计算瀑布流/相册坐标。`virtual-gallery.ts` 挂载视野和缓冲范围，默认缓存目标为 100 张卡片，活跃/聚焦节点优先；不会按固定页数截断记录。
- 日期时间轴和详情返回读取同一套数值坐标；未挂载的日期目标也能点击、拖动或键盘跳转。宽度改变后重新布局；详情期间变窄再返回时移除不属于新窗口的旧节点。
- 卡片离场释放媒体消费者和预览解码资源，不取消应用已接受的缩略图制作/保存任务。短距离往返保留已解码节点；普通刷新及详情回退按版本/来源继承封面，仍走资源校验。
- 批量计数/全选/Shift 范围和详情翻页按完整筛选集合处理。新窗口从当前选择状态恢复复选框；Tab/Shift-Tab 可跨窗口访问，焦点卡片不被滚动卸载。
- 真实窗口发现旧的整页 HTML 缓存复用了已消费的计划，导致重复解析后空白。大列表改为每次生成新计划；小列表缓存不变。动态标题观察器在重绑前取消，避免累计监听。

## 真实操作

使用自有隔离 Electron、真实测试媒体副本、1280×900 / 700×900 / 480×900、focus emulation。每类 1500 与 3000 条记录，记录拥有不同身份和日期，但复用部分物理媒体，不是 6000 个独立大文件的 I/O 压测。

- 两类历史均通过时间轴 End 到最后一条、真实鼠标拖动及日期点击；最后记录确实挂载，标题与详情身份正确。
- 瀑布流/相册互换以及宽窄窗口无卡片重叠。典型视口挂载 18–35 张；总数翻倍未让卡片 DOM 翻倍。
- 1500 条视频最后卡片返回顶部位置 560.73→560.73px，图片 557.75→557.75px；3000 条分别 560→560px、557.75→557.75px。
- 在中间位置进入详情，将视口从 1280 改为 700 后返回：同一锚点中心 397.60→397.83px；无残留窗口叠加，24 张卡片挂载。
- 第一条 Shift 选到最后一条，真实计数为 1500/1500 或 3000/3000；再次滚动后复选框仍全选。取消全选、退出批量、收藏筛选分别 1500→500→1500 / 3000→1000→3000，完整集合保持。
- 真实 Tab 从窗口最后卡片的最后按钮进入下一条；完整记录仍可经键盘访问。
- 两轮各 20 次快速主导航、20 个深处窗口切换：目标 History 正确、单列表，最大挂载 33 张，滚动采样无 50ms 以上长任务。GC 后 DOM 节点/监听约 24703/615 与 24708/614，未在这两轮持续增加；这不替代长期内存泄漏测试。
- 核心队列/草稿/视频与图片历史 SHA256 摘要在纯浏览检查中一致。
- 第 3000 条实际进入详情后回到创建，正确恢复 MiniMax H3 FL2VA。夹具历史含可选 Turbo LoRA，其缺核心依赖如实阻塞；通过原有移除按钮取消该 LoRA，再真实清空提示词→禁用→键盘恢复→鼠标入队，得到任务 `e7933d85-7a61-401f-96fb-0d964b3611fd`。未绕过门槛，队列保持暂停，未启动模型生成。
