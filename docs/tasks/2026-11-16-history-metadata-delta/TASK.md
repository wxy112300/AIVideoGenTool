# 历史收藏 / 评分 / 标签架构修复

- Status: done
- Impact: patch；不迁移用户资料，不改变磁盘格式，不安装/启动 ComfyUI。
- Baseline: 0.69.0，工作区开始时干净。前次11-15窄事务的性能结果仅覆盖存储，用户真实验收仍卡顿，不能视作完整修复。
- Execution: direct，无子代理。

## 已确认与方案

- 当前磁盘历史已按记录/正文分库，不是每次重写30MB历史；但元数据服务仍生成完整AppState，既返回又广播，前端再走全库比较。
- 第二热点是每次提交的备份retention遍历：反复读取/解析迁移前大份整库备份。只去全状态传输仍测到约90ms主线程停顿。
- 新增兼容IPC patchHistoryMetadata / history:metadata-changed，旧updateHistoryMetadata与batch API保留。新Repository端口只提取id/收藏/评分/标签，构造小结果，不克隆历史正文；仍复用同一串行事务和原持久化提交。
- renderer局部替换目标对象，保留versions/draft/其他记录引用；previous元数据条件使重复/旧ack无害，删除项不复活。收藏控件即时反馈，失败恢复。单条、标签、批量入口均接入。
- 备份retention只缓存已校验摘要，stat身份/大小/mtime/ctime变化即重读，读取权限错误仍上报；缓存不保留raw。恢复路径不使用摘要缓存，继续完整读/hash/schema校验；无效备份保留证据。
- 真实App暴露第三热点：后台NAS始终监听有效库提交，并非仅某个“启用”开关场景。原onCommitted仍生成全库快照、schedule再复制一份。新增窄onMetadataCommitted回调，NAS在父commit匹配时应用同一补丁；父提交/记录不匹配保留全快照回退，不改NAS发布/重试/撤回语义。
- 为避免首次点击仍解析冷备份，在加载阶段只预热retention摘要；不在该阶段删除备份。新事务的内部排队Promise单独处理拒绝，原调用者仍收到失败，后续操作可继续。
- 用户补充快速操作后切页：保存不随页面清理取消，回复按最新state合并；已卸载标签编辑器不再回焦/更新DOM。失败顶栏通知持久保留作品标题、收藏/评分/标签类型和详情动作，只有点击动作才跳转；标签失败不清空输入。

## 验证

- 新测试禁止新事务调用store.get或structuredClone非空历史，检查混合视频/图片持久化、重开、失败与小结果、无全状态广播；纯补丁检查引用、旧确认、重复事件和删除项。
- 原服务/动作/标签/renderer邻接定向64项通过；新增事务与备份20项通过。
- 1500条合成视频约30.6MB，对照同样持久化及模拟双向结构克隆：加入retention缓存后，旧全状态路径186.8–202.3ms、timer gap147.9–160.6ms；新delta31.1–46.0ms、gap5.6–15.7ms；回复约31.1MB→131字节。旧路径也使用新retention缓存，避免混淆收益。不是实际Electron逐帧证据。
- 首次真实Electron（尚未NAS增量/冷备份预热）收藏约519ms、标签约407ms，记录到58–132ms长任务；暖回放虽无长任务、帧间隔最大16.8ms，确认仍为收藏521ms/标签374ms。视频节点与标签焦点保留。这些失败结果保留，不能把合成数据当作真实验收；随后继续修复NAS与冷备份路径。
- 快速切页/失败通知/标签焦点与重试、事务/备份迁移回归41项通过，NAS真实副本增量与父提交保护16项通过。
- 证据：忽略目录temp/history-metadata-delta-20261116。最终完整门禁及真实Electron大库/失败跳转复验完成，不声称所有场景零停顿。
