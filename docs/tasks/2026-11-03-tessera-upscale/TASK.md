## 2026-11-22 adaptive performance work

- User requested RTX 4090 / hardware-VRAM-based execution instead of the fixed slow low-memory settings. Keep complete video, exact delivery canvas, three-step schedules, source audio and optional Qwen stage; do not substitute an interpolation-only output.
- Found that pixel Tessera/Refiner were classified as standard Upscale, with pinned memory and async offload disabled. The first candidate enabled native double-stream transfers plus larger tiles. Real partial 4K sampling under host memory pressure did not establish a speedup, so do not adopt unconditional pinning or larger tiles from GPU capacity alone. Installed 0.46 already auto-enables DynamicVRAM in the standard profile; the explicit native flag is not itself evidence of extra acceleration.
- Final policy reads backend `/system_stats` VRAM and available RAM during submission. First execution GPU owns the budget; free memory includes allocator cache, only live Comfy allocations are added back as reclaimable between stages. Do not sum GPUs. The 24GB budget requires >=22GiB total, >=20GiB usable after a 1GiB geometry cushion and >=32GiB available host RAM. Otherwise choose balanced at >=11GiB usable or low below that; absent telemetry retains legacy geometry. These heuristics never block admission or change the user's launch reserve.
- 24GB graph: Tessera upstream high_vram (1024 cap), 124-frame windows, 56-frame streamed encode; Refiner 1024x768 /136 frames. Balanced: Tessera low_vram spatial/73 frames/39 encode, Refiner 768x576/85 frames. Low: Refiner 640x512/68 frames and Tessera 73-frame windows. Local startup uses native double streams/pinned only with >=32GiB available RAM; otherwise `h3-upscale-streaming` uses one async stream and disables pinned memory. Compiler stays disabled for changing tile/LoRA shapes. Clear this ephemeral override for the next workflow family; saved settings/queue recipe are not migrated.
