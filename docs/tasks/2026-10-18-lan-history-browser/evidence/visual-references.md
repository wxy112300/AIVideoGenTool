# 移动视频浏览：逐屏参考与采用规则

- 类型：visual research；状态：已检查公开截图与文档，尚未验证产品原型。
- 日期：2026-10-18；适用：独立浏览网页的手机、iPad 与桌面布局。
- 当前状态：[TASK](../TASK.md)；方案：[DESIGN](../DESIGN.md)。截图归原发布者，仅作研究参考，不作为产品素材。
- 方法：下载并实际查看 10 张官方界面/宣传图片（Grok Imagine 3、小红书 3、PhotoPrism 3、TikTok 平板 1），补读 Pinterest、YouTube Shorts、Immich 官方交互文档。浏览器自动化运行时两次启动失败，因此本轮没有登录或实际操作这些 App/demo，不把静态图片当成完整交互证据。
- 参考优先级：按用户最新说明，GrokImage/Grok Imagine 是原 App 初始设计参考，作为本网页媒体陈列和视觉层级的主参考；小红书/TikTok 补充移动浏览与逐条观看方式，不把多个 App 的管理功能全部拼入界面。
- 最新方向：用户澄清以 Grok Image 手机 App 体验为主，一套移动优先设计适配 iPad/PC，不拆成两套体验；标题弱化，空间留给画面。下述早期参考中的“图片下短标题”是观察事实，不再作为本项目列表必须保留的标题行。现有 Grok 桌面演示仅作辅助视觉证据，不能替代尚未实际验证的手机体验。

## 1.1 Grok Imagine：媒体陈列的主参考

来源：[xAI 官方 Imagine Video 1.5，2026-06-16](https://x.ai/news/grok-imagine-video-1-5)。以下三张图片直接来自该页演示视频的 poster，已经实际查看；不是从模型输出样图推断产品 UI。用户指出 App 最初参考 Grok 的事实作为设计方向依据记录，不冒充本轮已从 Git 还原原始设计过程。

![Grok Imagine 官方项目与 Discover 结果墙](https://data.x.ai/releases/imagine/video-1-5/projects-poster.jpg)

观察：黑色/深灰底，主要区域是紧密排列的不同尺寸媒体，图片边界而非外套面板划分卡片，Discover 区几乎没有常驻长文案；顶部模板横带和左侧项目/历史属于创作工作区。采用媒体优先、紧密节奏和低文字密度；在浏览页用紧凑 Filter/排序替代模板与生成输入框，不复制截图中的桌面侧栏宽度或列数。

![Grok Imagine 官方多任务画布演示封面](https://data.x.ai/releases/imagine/video-1-5/multiple-agents-poster.jpg)

观察：生成结果以媒体本体呈现，工具以小型图标聚集在边缘，正文信息克制；画布包含缩放/编辑工具。这支持内容与辅助工具分层的视觉方向，但本网页仍采用可滚动列表与全视口播放器，不采用可拖动无限画布。

![Grok Imagine 官方搜索演示封面](https://data.x.ai/releases/imagine/video-1-5/search-poster.jpg)

观察：多个结果组保留各自媒体比例，在同一暗色背景上以空间组织；视频卡片带简短播放状态，整体没有大量参数块。借鉴同一视觉语言下的媒体混排与轻状态；本项目排序/筛选和资产身份保持现有语义，不从截图引入组管理、语义搜索或额外数据库。

补读 [Imagine Image 2.0 官方说明](https://x.ai/news/grok-imagine-image-2)，用来确认产品入口及图像/视频创作上下文，不把模型生成的示例图片当作 UI 截图。`grok.com/imagine` 在本轮网页读取中没有暴露可分析的完整界面；未取得已登录手机端和单条查看器实测。因此不能声称已验证 Grok 的信息显隐、长按或滑动手势，相关动作继续以用户要求和后续原型操作为准。

## 2. 小红书：双列发现 → 详情 → 视频

来源：[小红书官方 App Store](https://apps.apple.com/cn/app/id741292507)。以下为开发者发布的推广截图；推广标题/手机装饰框不进入产品设计。

### A. 双列首页

![小红书官方双列发现页](https://is1-ssl.mzstatic.com/image/thumb/PurpleSource211/v4/54/d6/77/54d677a9-b6e1-2e3d-a2b4-6e6b2f202ec1/1.jpg/300x650bb-60.jpg)

观察：两列媒体高度不同，图片下短标题，卡片没有外围大面板；图片角落有轻量媒体类型标记。采用双列密度和轻量层级。筛选、排序与视图替换这里的社交频道；项目没有多目的地时无需底部 tab bar。

### B. 单条图文详情

![小红书官方笔记详情](https://is1-ssl.mzstatic.com/image/thumb/PurpleSource221/v4/4f/fe/ce/4ffece29-dc74-ae05-0b04-864c65142573/2.jpg/300x650bb-60.jpg)

观察：主媒体保持较大高度，返回在顶部，底部互动与长正文分离。借鉴返回和主媒体层级；本项目视频观看不采用长正文区，避免变回桌面 History 参数详情。

### C. 视频观看

![小红书官方视频观看页](https://is1-ssl.mzstatic.com/image/thumb/PurpleSource221/v4/90/5e/b6/905eb672-5707-54e5-990d-4d67bfd85baf/3.jpg/300x650bb-60.jpg)

观察：视频占据主区域，左上返回，信息落在下部，底部操作较轻。采用覆层方式，不在视频外套大卡片或额外页头。该截图看不出中心暂停/长按倍速/信息显隐行为；这些以用户需求与后续实现测试为准。

## 3. TikTok：iPad 横竖屏

来源：[TikTok 官方平板设计说明，2023-12-18](https://newsroom.tiktok.com/larger-screens?lang=en)。这是带日期的历史设计参考，不声称是 2026 年所有地区的最新界面。

![TikTok 官方平板横竖屏配图](https://p16-tiktokcdn-com.akamaized.net/obj/tiktok-obj/847fdeac67e66d3467abbaa0d9a01ab6.jpeg)

观察：横屏竖视频居中，左右留深色区域，信息和动作分布在可用空间；竖屏仍以视频为中心。本项目据此做独立的横竖屏排布，不把手机布局等比拉大。iPad 列表虽然增加列数，仍属于移动端精简布局，不重新加入日期轨道。

另外阅读了 [TikTok 网页布局更新，2025-02-27](https://newsroom.tiktok.com/new-features-bring-tiktok-magic-to-desktop?lang=en)，但下载的该页 OG 图仅为 logo，已排除，不能把它当作网页 UI 截图。首页/观看流程只借鉴所述媒体优先与减少干扰方向，不据此编造控件位置。

## 4. PhotoPrism：比较信息密度

来源：[PhotoPrism 官方 Result Views](https://docs.photoprism.app/user-guide/search/views/)。图片文件名带 2503/2502，为官方文档静态参考，不是本轮设备操作截图。

![PhotoPrism 带元数据卡片](https://docs.photoprism.app/user-guide/organize/img/card-2503.jpg)

观察：卡片下方标题、时间、文件等内容明显占高。它用于说明管理视图的信息成本，本项目不复制这类长元数据块；卡片保留短标题/时长足够。

![PhotoPrism 密集相册](https://docs.photoprism.app/user-guide/organize/img/mosaic-2503.jpg)

观察：密集媒体网格将空间留给内容，收藏标记叠在媒体上，顶栏提供视图切换。本项目相册模式采用规整网格与轻标记；具体两列/多列由自己的可用宽度决定，不照搬该桌面截图的列数。

![PhotoPrism 黑底查看器](https://docs.photoprism.app/user-guide/organize/img/slideshow-2502.jpg)

观察：媒体完整显示在黑底中，标题和工具独立于媒体。本项目采用完整画面与克制信息；移动端将三种整理动作置于拇指更容易触及的下部，移除这张图中的下载/编辑等管理工具。

## 6. 原型采用标准

以下是综合参考后的项目设计值，尚待实际截图判断，不是参考 App 的测量结果：

- 手机 390px：左右约 10px、列间 8px、两列约 181px；边缘不留日期槽位。较窄手机也保持两列，极端放大/不足 320px 才恢复单列。
- 顶部约 52px 工具栏，筛选激活才出现约 32px 摘要；没有大 Hero、第二层导航、空用途底部 tab 或常驻筛选表单。
- 两端列表默认无独立卡片标题/说明行，空间留给媒体；保留可访问名称，PC 的短标题可在 hover/focus 时轻量出现，手机打开观看后再按需查看；时长等必要状态只作轻标记。
- 手机观看页：左上返回、左下弱化的一行标题/极少元数据、右下三个整理按钮；进度条细但命中区足够；纯观看时信息与按钮一起隐藏。iPad/PC 延续相同观看模式和信息层级，适配媒体舞台尺寸、控件位置与鼠标/键盘输入，不另设计一套详情体验。
- 以 Grok Imagine 的暗色媒体墙和克制工具层级作为视觉主线；一个明确强调色，沿用语义 token，不复刻其他产品品牌色；不用多层描边卡片、重阴影、大面积玻璃模糊。
- 分别提交手机、iPad 和 PC 对照稿，使用竖/横视频、不同封面比例、长短标题、评分/未评分和真实缺图状态，至少覆盖 390×844、820×1180、1180×820、1440×900。iPad 变宽仍需触屏可操作，不因断点切成 hover 才能使用的界面。静态稿之后仍须操作验证长按/切换/抽屉/返回及 PC 鼠标/键盘，不以“像参考图”替代可用性。

下一阶段先展示列表、观看信息开启/隐藏和 Filter 抽屉这几类实际画面，再按反馈调整布局；已有桌面组件与 ASCII 示意仅作功能基线，不充当视觉通过证据。密码/数字配对依最新指令留到可选最后阶段，不纳入首轮视觉或 LAN 验收。
