# 历史收藏、评分、标签保存性能

日期：2026-11-15 · 类型：patch · 状态：实现与验证完成

- 授权：排查并修复收藏、评分后的卡顿，用户补充标签编辑也卡；覆盖单条和批量标签，保留UI和现有数据格式、IPC。
- 热点：语言读取调用store.get复制全库；通用update复制整个state用于回滚，persist再复制一次；Library.prepare全库JSON往返，RecordStore再逐记录canonical，包括长提示词和工作流正文。已有renderer正文比较排除curation变化，不能把这次问题简单归因为整页重绘。
- 实现：StateRepository可选updateHistoryItems端口，JsonStore在原updateChain内只克隆选中记录、复制集合索引；只读保留其他历史对象，非历史状态仍做快照。回滚恢复原集合，身份不可改变；原update路径继续保留。生产MigratingUserDataRepository绑定转发该方法，元数据服务读取getSettings并优先窄更新，无此能力的兼容repository走原路径。
- 分库：只归一化/编码选中或未缓存记录；复用未改记录前要求已验证hash等于真实父提交hash，避免未激活prepare污染缓存。冷缓存/路径变化仍归一化并核验，原格式、对象不可变、原子替换、备份和失败恢复不变。队列瞬态更新只作用queue，不改历史记录。
- 自动验证：保存后重开、视频/图片混合编辑、不改记录hash稳定、回调/磁盘失败回滚重试、缺失记录原子失败、父提交缓存隔离、冷缓存归一化均覆盖；生产包装器、收藏按钮快速点击/同步及标签交互也回归。
- 性能：独立合成1500条视频、30,573,217字节，旧get+通用update和新getSettings+窄update交替三轮，含持久化、相同onCommitted回调与返回快照。旧458/398/370ms，新213/291/201ms，中位398→213ms。另一次旧380/373/372ms，新200/200/303ms。均为存储路径，不是用户真实窗口/完整IPC端到端；并发检查下1ms timer gap未显示一致最大停顿改善，不宣称零长帧。仍保留全量广播/返回状态与发布快照，其成本未被此次消除。
- 临时证据：temp/history-metadata-20261115及temp/history-metadata-verify-20261115，使用独立OS临时库并在验证路径后清理；不读写真实用户历史，不启动应用/ComfyUI或GPU。主工作区dist未改。
