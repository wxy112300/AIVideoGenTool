# 队列松手卡顿

类型：patch · 状态：完成

- 用户反馈：排序已保留封面，但松手仍卡顿，随卡片数量增多而加重。
- 原因与修复：setRendererState 每次确认都会写相同 lang/主题属性，触发整页样式/文本布局；现按值比较后写入。共用观察器只为未初始化控件刷新，移动旧卡不重扫；真实卸载会忘记标记，重新挂载或混合新增仍正确。编号 aria-label/deferred 属性跳过相同写入。拖动规则缩到把手，保留原 Grid、卡片尺寸与媒体节点。
- 真实大队列实测还发现 Chromium 会在主键仍按住时丢失捕获；现允许已有 window 指针监听继续接收，up/cancel/blur 仍结束。专项覆盖此分支及键盘、暂停边界。
- 基线：100 卡片控件重复处理 400 次；300 卡片 1200 次、最大帧间隔 66.7ms，有 66ms/54ms 长任务。最终 300 卡片两次实际拖动：最大帧间隔 16.9 / 16.8ms，P95 约 16.8ms，50ms 以上长任务 0，控件重复处理 0，图片重载 0，原图片节点/src 保留；第二次验证 grabbing 光标、松手截图和键盘恢复排序。合成等待任务与同一已解码 PNG，仅证明本机该 DOM/交互场景，不外推真实 GPU 或任意规模。
- 验证：最终专项 47 项、类型检查、独立生产构建、集成 127 项与 440 对比度项通过。共用状态/观察器全量单元 3195 项通过，其后增加的捕获分支 9 项单独通过并纳入最终专项。首轮单元因隔离快照缺 temp 目录导致 3 项剪贴板检查未执行，补齐目录后单独 3 项通过，后续全量通过；未改断言或测试超时。
- 证据：忽略目录 temp/queue-drop-*.log，基线 report/trace；最终 temp/queue-drop-accepted-300-4wb5kw/report.json、temp/queue-drop-acceptance-repeat-300-nYzp31/report.json 与 queue-after-drop.png。独立构建不改主 dist；隔离 userData/端口、队列空闲，未启动 ComfyUI/GPU。自有窗口/端口退出，依赖链接已移除。并行模型卡片修改保留。
