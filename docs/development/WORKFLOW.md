# 单 agent 优先的开发流程

更新：2026-09-09。目标是减少 Expensive Parent Participation，并限制整个 Agent Tree；替代此前固定的“Astra/Sol 规划与集成、Luna 执行”策略。

## 默认执行与例外

当前 agent 独立完成理解、调查、实现和验收。Luna 可独立完成文档整理、有界修复和升级；Astra/Sol 可直接完成复杂调查与实现。角色不绑定模型，不为每个阶段创建一个 agent，也不要求 Luna 的成果常规送高级模型复核。

先用 rg、脚本筛选/聚合数据。高级 agent 已经理解问题时，直接修改通常比重新编写工作包更省。复杂任务可以分阶段，但阶段不是子 agent。

仅当以下条件同时成立才例外派发：
- 有大量尚未由父 agent 完成的独立工作，交付会替代父级工作，而非额外提供一份意见。
- 输入、文件归属、停止条件和验收可一次讲清，预期不需要持续辅导。
- 父 agent 同时有有用且不重叠的工作；没有则直接执行，不为维持并行而制造工作。
- 粗略判断“派单 + 子 agent 上下文/执行 + 父级验收 + 返工”低于直接完成的成本。没有理由支持则不派发，不做昂贵的成本研究。
- 本请求尚有树预算。用户明确要求多 agent 时遵守其范围并记录本次上限，不自动扩大到未指定部分。

## Agent Tree 上限

这是仓库行为约束，不是已安装的平台限流器：

| 项目 | 默认 | 例外派发上限 |
| --- | --- | --- |
| 累计新增子 agent | 0 | 每项用户请求总计 1 |
| 最大深度 | 0 | 1，子 agent 禁止再派发 |
| 同时运行子 agent | 0 | 1 |
| 工作包 | 当前 agent 直接做 | 1 个完整交付，含对应验证 |
| 父级介入 | 无派发开销 | 1 次派单 + 1 次验收；必要时最多 1 次纠偏追问 |

累计创建包括失败和替换 worker；不能通过关闭重建、后续回合、压缩上下文、连续批次或换模型刷新额度。现有请求已超过上限时不再扩张，完成或收口已有工作；不擅自停止其他独立用户任务。额度用尽后当前 agent 继续做，不默认请用户批准扩容。

禁止通过新用户任务、CLI/API agent 或嵌套 reviewer 绕过限制。脚本数据处理不算 agent，但不得在脚本里再调用模型规避计数。只有用户明确改变范围/上限才调整，记录在当前 TASK 或简短工作记录中。

## 减少昂贵父级参与

- 一次发出目标、必要约束、精确输入、独占文件、验收、有限处理范围/尝试次数和停止条件；不要先替 worker 做完调查再派单。
- 使用当前工具支持的显式模型和 effort；有成本理由时可选 Luna，遵守用户指定。使用最小上下文（本环境支持 fork_turns: "none"），不复制完整会话；保留所有必要授权与约束。
- 不默认 Max，不静默继承昂贵父模型。指定模型不可用则直接完成，不自动创建高成本替代 worker。
- 子 agent 执行整个有界交付并做对应检查；常规实现选择自行决定，最终只回结论、改动/证据路径、检查结果、未决项。异常只在需要决定或授权时报告。
- 父级不重复读取其原始资料，不周期性 read_thread/查询状态，不把每条进度转述成新一轮分析。需要等待时用事件/有界等待，保持必要用户沟通，不轮询制造上下文。
- 验收查看最终 diff、必要上下文与关键证据。高风险问题必须核实，但不自动生成第二份研究或 reviewer。若需要重新做大半调查，停止这次分工并由当前 agent 接手。
- 最多向同一个 worker 发一次纠偏追问；仍不清楚则当前 agent 接手或说明真正阻塞。安全/授权问题必须处理，不能为遵守回合目标省略；同时不因此重开 worker。
- 减少父级参与不是降低质量：产品契约、静态与真实运行证据区分、必须的验证层级保持不变。

## 一条流程，按风险取必要步骤

理解/复现 → 有界调查 → 决定最小改动 → 实现 → 对应验证 → 交付或记录阻塞。

小修不强制 TASK、PLAN、ADR、研究报告或多人审阅。跨会话/长任务复用一张 TASK，保留当前结论和下一步；只有复杂依赖确实需要时才拆 PLAN。
例外派发只替换其中一段完整工作，不改变当前 agent 对任务结果的责任。

<a id="bug-fix"></a>
### Bug 修复

理解触发、期望/实际，定位错误链；当前 agent 修改并验证原触发与相邻行为。回归测试要能捕获缺陷，不镜像实现。不确定时明确缺失条件；不为一次修复另开“调查员 + 实现员 + 审阅员”。

<a id="integration"></a>
### 新节点 / 新图像编辑模型

先核对固定 repo/revision、许可证、Windows/Python/Torch/CUDA、模型目录、实际 node schema/API graph 与安装副作用，再实现 catalog/adapter/设置/queue/history。文件检测、schema、graph、最小真实输出、产品闭环分别验收；大权重按现有用户管理边界处理。大包递归检查可符合例外，但必须替代父级读取，不能同时双查。

<a id="upgrade"></a>
### 已有节点 / 插件 / 工作流升级

固定当前与目标 revision；比较源码/schema、requirements、资产 hash 和兼容补丁；保持参数/ID，定义备份/回退与重启窗口。验证旧队列/历史及适用 smoke，不顺带启用新增功能。必要证据写本 TASK 的 evidence/upgrade.md；未实际验证回退时写明，不能声称可回退。

<a id="prompt"></a>
### Prompt 增强研究

先定假设和评价维度，再整理来源与小样本候选。固定模型/revision、素材、seed、采样参数，对照语义保真、动作/镜头与连续性，保留失败案例和耗时。需要持久证据时存 evidence/prompt-eval.md。社区经验是候选假设，未测质量不替换默认 Pack，不覆盖用户自定义内容。

<a id="extension"></a>
### Extend / 长视频方案

核对 artifact、边界帧、音频/latent、时长限制和旧失败证据；区分边界帧续接、Motion Context、Native AV。先 A→B，再 A→B→C、取消/恢复/历史关联；每次只扩大一个维度，预定资源与时间上限，失败后改假设，不循环扩帧。默认由当前 agent 完整负责，不按阶段拆树。

<a id="blocked"></a>
### 被卡方案

记录精确阻塞、已排除假设、固定版本/hash、解锁条件和最小下一实验。相同条件复用负结果；仅在来源/环境变化或证据不足时重查。明确淘汰的方案保持归档，例如 [DLSS5](../archive/dlss5/README.md)，不因新会话自动重启。没有新证据时不派 worker 再调查一遍。

## 验证、资源和计量

按 [CHANGE_VERIFICATION](../CHANGE_VERIFICATION.md)选择检查。任何执行者在同一整合文件状态已完成、且有可核对命令/结果的检查可复用；focused check 不替代必须的 full gate，但不因执行者不同重复同一个 gate。关键文件变化、失败或证据缺口才重跑受影响检查。

保持一文件一写者；dist、GPU、ComfyUI、端口/userData 都须协调。worktree 不隔离机器资源，不终止其他任务进程。归属记录不是锁。

只记录能获得的数据，优先复用工具统计：实际模型/effort、累计子 agent/深度、纠偏次数、父级派单/验收外介入、全树 input/output/reasoning/cached token（工具可见时）、耗时和返工。不可得写 unknown；不要把便宜 worker 的 token 当作昂贵父级 token 已减少。原始 token、实际费用与账户额度分别看，不能用无依据的固定权重换算。

有代表性任务的历史可比数据时比较；不为了证明节省而把同一任务重做两遍。目前上限是保守工程选择，不承诺实测降幅，不修改全局模型/限额配置。
[官方 Subagents 文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)说明每个子 agent 都增加自己的模型与工具工作；本仓库因此采用默认单 agent。
