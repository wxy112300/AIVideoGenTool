# 混合 agent 开发流程

适用：bug、新节点/模型、已有插件或 workflow 升级、prompt、Extend/长视频、运行时阻塞。
维护原则：一个任务一个负责人、一份可续接摘要；详细材料按需读取。

## 为什么重建

问题不只是 AGENTS 太长，而是事实/计划/证据/历史混写、任务缺少可恢复状态、调查产物不断灌入高级 agent 上下文。优化目标是减少重复阅读、无效实验和高级模型机械劳动，同时保留可复核证据。文档变短不等于实际账单下降。

## 默认职责

| 角色 | 默认模型偏好 | 输入 → 交付 | 不应自行决定 |
| --- | --- | --- | --- |
| 任务负责人/规划者 | Astra 或 Sol，沿用用户选定模型 | 用户目标 + 有界证据 → 范围、决策、工作包、最终验收 | 其他独立任务的资源和优先级 |
| 调查/数据 worker | Luna | 固定来源/问题 → 版本差异、schema、hash、匹配项和反证 | 以安装成功代替可运行结论 |
| 实现 worker | Luna，明确复杂逻辑可提高 effort | 可执行工作包 → 局部补丁、focused tests、短交接 | 扩大产品范围、改变 persisted ID、跨模型 fallback |
| 集成/复核 | 本任务 Astra/Sol 负责人 | diff + 关键证据 → 接受/修正/下一包 | 从 worker 摘要直接宣称真实 smoke |

高级 agent 可以直接实现复杂部分，不必为了分工而等待 Luna；Luna 不仅做数据整理，也可完成边界明确的实现。小修由当前 agent 直接完成，不强制唤醒高级模型。碰到不明确的产品决策，Luna 返回精确问题和已完成证据；能联络已指派负责人就交接，否则继续无依赖部分，不自行创建新用户任务或冒充另一模型。

### 派发设置

使用本次会话实际提供的模型 ID 和工具参数。当前可用时，批量 worker 显式选择 `gpt-5.6-luna`；简单盘点用 low/medium，代码追踪/实现通常 high，max 仅针对明确需要。不能只在提示词里写“你是 Luna”而让工具继承 Astra。

本环境支持 `fork_turns: "none"`：默认发精简工作包，不复制整个对话；仍必须给出用户约束、源文件、验收和必要契约。依赖连续调查的追问复用原 worker，只发送差量。工具不支持显式模型或 Luna 不可用时，说明限制，按当前模型本地完成或使用已授权替代，不静默扩大昂贵并行。

通常保持 1 个负责人 + 1–2 个独立 worker；这是项目启发式，不是平台上限。只有独立工作与主线程有效工作同时存在时才派发。worker 默认不递归派发；确需进一步拆分先交负责人调整工作包。

## 两条执行路径

### 短路径

适用于原因清楚、范围局部、没有新的 persisted/工作流/运行时策略的小修：

理解/复现 → 当前文件局部修改 → focused tests + 对应验证层级 → 交付。

计划写在当前任务即可；不强制 TASK、研究报告、ADR 或第二个 reviewer。发现跨模块/运行时风险后升级标准路径，而非硬做到底。

### 标准路径

1. **Triage**：负责人确定目标、保留项、风险与成功标准。搜索已有 TASK；复用同主题当前任务，不开 v2/v3 计划树。
2. **Evidence**：Luna 批量读取/比较；负责人同步检查受影响架构和关键代码。先便宜地排除硬阻塞，再下载大包或进入 GPU。
3. **Decision**：负责人选定最小方案、替代方案取舍和阶段停止条件。授权范围内直接决定；只有缺少用户产品选择/授权才提问。
4. **Execution**：Luna 接受独占文件工作包；负责人处理复杂集成/共享类型。相同文件串行，不用“分别改不同函数”假定无冲突。
5. **Integration**：负责人重新读取当前 diff，复核高风险证据，执行 [验证分级](../CHANGE_VERIFICATION.md)。worker 的 focused check 不替代整合后的 gate。
6. **Close or Block**：更新 TASK 的结论、证据和下一步；稳定产品约束归入契约，版本变化进入 changelog。研究完成可 DONE，生成未验证须写在成果边界中。

任务状态：`triage → investigating → ready → implementing → validating → done`；任一步可 `blocked` 或 `superseded`。blocked 解除后回到具体步骤。这里是 Markdown 任务状态，不是 Codex goal/automation 的状态；不创建后台监控、不修改工具状态。

## 各类任务最小工作包

<a id="bug-fix"></a>
### Bug 修复

- 负责人：记录触发、期望/实际、受影响路径；优先复现或解释失败。
- Luna：定位错误链、筛选日志、补一个能捕获真实缺陷的回归测试，或实现指定模块修复。
- 验收：原触发 + 相邻行为；不要用一堆镜像实现的断言制造覆盖率。不可复现时标明推断与缺失条件。

<a id="integration"></a>
### 新节点 / 新图像编辑模型

- Luna 先交证据表：官方 repo/release/commit、许可证、Windows/Python/Torch/CUDA 条件、模型目录、真实 node schema、官方 API graph、安装副作用。
- 负责人判断是否具备最小运行链路，再定义 catalog/adapter/设置/queue/history 的集成包；不能先把下拉框做完就算接入。
- 分阶段验证：文件检测 → schema → graph → 最小真实输出 → 产品闭环。阶段可分别记录，不混成“已支持”。
- 大权重仍按产品现有下载边界处理；仅为调查不自动下载全部权重。

<a id="upgrade"></a>
### 已有节点 / 插件 / 工作流升级

- 先固定“当前 revision → 目标 revision”；Luna 比较 release、源码/schema、requirements、资产hash和本地兼容补丁的适用性。
- 负责人选择必要改动，明确保留现有参数和 ID、备份/回退、重启和验证窗口。
- Luna 在独占 adapter/catalog/test 范围执行；安装或 runtime 更新依照现有服务流程，不在共享 ComfyUI 上并发操作。
- 验收旧队列/历史兼容与对应真实 smoke；不顺带启用上游新增功能，不以“latest”代替固定版本。
- 将差异和回退检查写入本 TASK 的 `evidence/upgrade.md`；在隔离副本或已协调环境验证恢复旧版本/配置。若只审阅回退方案，明确标为未执行，不冒称可回退。

<a id="prompt"></a>
### Prompt 增强研究

- 负责人先写可检验假设：例如“改善续写边界动作连续性”，并定义评价维度。
- Luna 整理官方/社区来源、当前模板、代表性匿名用例和候选改写；社区经验标为假设。
- 对照固定模型/revision、参考素材、seed、采样参数；先小样本筛选，再由用户或明确评分标准评估语义保真、动作/镜头、边界连续性。
- 保存失败案例、耗时和输出引用；未测质量不直接替换默认 Prompt Pack，不能覆盖用户自定义 prompt。
- 对照结果保存为本 TASK 的 `evidence/prompt-eval.md`，列输入编号、版本、参数、评价方法和失败反例；原始媒体仍在忽略目录。

<a id="extension"></a>
### Extend / 长视频方案

- Luna 提取现有输入/输出 artifact、边界帧、音频/latent、时长限制、依赖与已知失败证据。
- 负责人先决定“边界帧续接 / Motion Context / Native AV”的精确范围及恢复策略，避免把不同能力混成一个“长视频支持”。
- 最小试验先验证 A→B，再验证 A→B→C、取消/重启与历史关联；验证连续性和声音，而非只看容器时长。
- 每次只放大一个维度，运行前确定 GPU/内存/时长上限和清理责任。达到失败阈值就保留证据并改假设，不循环扩帧重试。

<a id="blocked"></a>
### 被卡方案

用 [TASK 模板](TASK_TEMPLATE.md)保存：阻塞的精确边界、已排除假设、最后一次证据、触发条件和最小下一实验。

同版本/同 hash/同前置条件的否定结果优先复用；只在输入改变、证据范围不足或明确推翻旧结论时重查。外部依赖被卡不能写成产品永久不可能，也不能把旁路 provider 的成功当作解锁。实例如 [DLSS5](../tasks/2026-09-07-dlss5-runtime/TASK.md)。

## 上下文与成本纪律

以下是可调整的阅读/输出目标，不是硬 token 截断，也不是工具预算：

- 根 AGENTS 目标约 6 KB 以内；只放跨任务不变量与入口。
- 负责人初始包：TASK 摘要 + 一条流程 + 必要契约章节 + 关键源码，不读全文档库存。
- 工作包通常 300–700 字；返回通常 500–1000 字以内。不能为限长省掉复现命令、失败、hash或反证；超长细节落文件并给精确定位。
- 先 `rg` 定位，再读片段；高容量数据用脚本解析、计数、过滤，避免主线程逐页读完整 JSON/archive/log。
- 下载只需检查一次：证据带 URL、revision、SHA-256、字节数、命中成员/负结果计数、范围和方法。原始包放忽略目录，交接不贴完整成员表。
- 源码当前状态/外部版本变更会使旧证据失效；记录失效条件，不定期无理由重复全查。
- 每个决策/阶段完成时覆盖更新 TASK 的短摘要；详细证据另存，禁止反复追加整份会话 recap。上下文紧张时先落盘再继续，其他 agent 只需 TASK 即可恢复到下一步。
- Luna 同一阻塞尝试两种有依据的方法仍无进展时，交负责人改变问题或缩小范围；禁止相同命令无变化循环。这是项目调度规则，不覆盖工具自身状态规则。
- 验证失败先分类：自己的改动、并发变更、环境、上游；修受影响范围，不借机接管所有红灯。
- 不用频繁轮询制造上下文；结果有意义或需要决策时才交接。

记录实际可获得的调用量/usage、worker 数、重复读取/重复实验、返工次数和完成用时；无法取得 token 计量时写 unknown。用 3–5 个实际任务评估，而不是宣称多 agent 一定更省。

## 文件与运行资源协调

TASK 记负责人、允许文件、读写资源、当前持有者和释放状态。跨独立任务通过可用协调工具确认；表格仅是可见记录，不是原子锁。无法确认共享文件/运行资源归属时继续只读/独立工作。

构建清理 `dist`、生成脚本输出、安装节点、占用 GPU、启动/重启 ComfyUI 均须串行协调。worktree 仅隔离代码；测试还要分开端口、userData、state/media。不能改默认用户目录或终止另一任务进程来获得结果。

## 文档与会话工具边界

本流程通过仓库指令和工作包生效，不安装自动调度器、不改变账户限额，也不自动改全局模型配置。已运行的其他任务应在续接时重新读当前 AGENTS/TASK；本任务不主动向独立用户任务发送消息。

官方文档说明了用子 agent 隔离原始材料、显式选择模型以及额外 token 开销；本仓库的角色和长度目标是用户偏好下的工程选择：[Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。
