# 文档职责与生命周期

## 一份信息只有一个维护位置

- **规则**：AGENTS 只放跨任务约束和读取路由；不放模型版本、长日志、固定历史 phase。
- **契约**：保持当前产品承诺；变更由当前任务执行者按授权审阅，引用必要 ADR；不强制增加高级 reviewer。调查/单次实验不能直接变成产品约束。
- **TASK**：本次目标、状态、下一步与文件归属唯一来源；目录名、计划标题和聊天最后一句都不是状态数据库。
- **Plan**：只在 TASK 放不下复杂依赖时拆出；只描述待做决策/步骤，不复制产品规范。
- **Research / Evidence**：保留来源、时间、范围、负结果和失效条件；研究由负责人决定是否采用。实验报告不写成永久保证。
- **Runbook**：可重复执行的步骤、前置条件、预期输出、失败/清理路径；真实执行结果写 evidence。
- **ADR**：长期架构取舍及后果；不为每个小修新增 ADR。
- **Archive**：历史追溯，只读参考；不作为新工作默认入口。
- **Changelog**：发布变化；不充当计划、操作手册或任务台账。

目录与当前入口见 [文档首页](../README.md)。新任务放 `docs/tasks/`；新长期研究/手册分别放 `docs/research/`、`docs/runbooks/`；不再新增顶层 `*_PLAN.md` 或 `Plan/active/vN` 分支。现有契约继续原路径，避免全库链接震荡。

## 维护责任与长度

当前任务执行者维护 TASK、决策、证据与文档，可由 Luna 独立完成；不固定拆成规划/执行/复核三个角色。每个文件只有一个写入者，任务结束释放；“高级 agent”不是跨任务永久文档管理员。

新研究/计划/手册开头写：类型、状态、日期、适用范围、权威/替代链接。已有文档在被维护时补，不启动全库无差别格式改写。
TASK 当前摘要尽量一屏；AGENTS 目标约 6 KB。长证据在细节文件里，索引只放路径和分类。超过目标是拆分提示，不硬删重要约束。

## 旧文档迁移

迁移分两层：先修默认入口和分类，再按明确证据迁移物理路径。旧文件有活跃使用者或正在变更时保留原路径。

1. 当前执行者盘点标题、类别、声明状态、重复与反向链接，形成 [清单](DOCUMENT_INVENTORY.md)。未核验完成度写 unknown，不根据日期判 done。
2. 同一执行者检查候选的当前契约/代码/较晚证据；确认哪些是被替代，哪些仍含唯一要求、用户停止指令或待办。
3. 对继续做的主题，建一个 TASK，提取当前范围/阻塞/下一步，引用旧证据。旧 plan 不必重写成新计划。
4. 对确定被替代的文件，协调文件归属后移动到 `docs/archive/<topic>/`；Windows 移动前校验源/目标绝对路径在仓库内。更新入口与反向链接，必要时在旧路径留短跳转说明。
5. 用 `rg` 搜旧路径、检查新链接和 diff；保留日期/来源/历史结论原貌。先证实无唯一信息再考虑删除；本次默认不删。
6. 不将 `Plan/archive` 与 `archive` 两棵树自动合并。先统一逻辑入口，再逐文件确认搬迁，避免跨任务覆盖。

## 检查与衡量

文档变更检查：本次链接可解析、引用脚本存在、职责/状态没有重复权威、没有错误提升 runtime 结论、没有意外删除。单纯文档不运行应用 build/GPU。

不要为整理强制阅读所有旧文件全文；标题/状态足够分类，只有判断替代或提取唯一要求时才深入。盘点是带日期的快照，新文件由 docs 首页/TASK 入口管理，不把盘点当第二份实时状态表。
